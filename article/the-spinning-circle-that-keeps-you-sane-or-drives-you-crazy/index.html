The Spinning Circle That Keeps You Sane (Or Drives You Crazy)

by
Jorrik Klijnsma

A small animation sits between your click and your result. It's either the most reassuring thing in the world, or it makes you want to throw your laptop out the window. Loaders are weird. They don't do anything. They're just there to tell you something else is doing something. And yet, when they're missing, you feel lost. When they're too slow, you feel cheated. When they're too fast, you wonder if they even tried.

This is a deep dive into that spinning circle. And the bouncing dots. And the morphing shapes. And the full-screen animations that make you almost forget you're waiting. Not the backend stuff, not the API calls, not the connection timeouts. Just the animation itself. How it looks, how it moves, how it tricks your brain into patience, and how to build one from scratch.

We'll go from dead simple to borderline overkill.

Your Brain On Loading

Here's the thing about waiting: it's not the time that bothers you, it's the uncertainty. A watched pot never boils, but a pot with a timer feels fine.

Loaders work on the same principle. They're a visual promise that says "hey, I'm working on it." Without them, users start wondering. Is it frozen? Did my click register? Should I refresh? That moment of doubt is poison for any interface.

The psychology is simple: acknowledged waiting feels shorter than unacknowledged waiting. Studies have shown people perceive the same duration as 36% shorter when something visual confirms their action was received. That's not nothing.

But there's a flip side. A loader that shows up too often trains users to expect slowness. A loader that spins forever with no progress indication builds anxiety. A loader that appears for 50 milliseconds just creates visual noise.

The sweet spot is somewhere around 200-500ms. Anything faster than 200ms doesn't need a loader at all, your interface should just respond. Anything that takes longer needs acknowledgment. And anything over 10 seconds needs something more than just a spinner, it needs progress or at least some text explaining what's happening.

Now let's build some.

Level 1: The Ellipsis

The most basic loader there is. Three dots. That's it. You see this everywhere someone is typing in a chat.

 

<div class="ellipsis-dots">
  <span></span>
  <span></span>
  <span></span>
</div>

 

.ellipsis-dots {
  display: inline-flex;
  gap: 6px;
}

.ellipsis-dots span {
  width: 8px;
  height: 8px;
  background: #667eea;
  border-radius: 50%;
  animation: ellipsis-fade 1.4s ease-in-out infinite;
}

.ellipsis-dots span:nth-child(2) {
  animation-delay: 0.2s;
}

.ellipsis-dots span:nth-child(3) {
  animation-delay: 0.4s;
}

@keyframes ellipsis-fade {
  0%, 80%, 100% {
    opacity: 0.3;
    transform: scale(0.8);
  }
  40% {
    opacity: 1;
    transform: scale(1);
  }
}

 

The staggered animation-delay creates a wave effect. Each dot fades in and scales up slightly after the previous one. The combined opacity and scale change makes the animation feel more alive than just fading alone.

The timing here matters. 1.4 seconds for a full cycle, with each dot peaking at 40% through. Fast enough to feel responsive, slow enough to not be frantic. Soft, unobtrusive, gets the job done.

Level 2: The Classic Spinner

The border trick. A circle with one colored edge, rotating forever. This one's been around since the dawn of CSS animations.

 

<div class="spinner"></div>

 

.spinner {
  width: 44px;
  height: 44px;
  border: 3px solid rgba(102, 126, 234, 0.2);
  border-top-color: #667eea;
  border-radius: 50%;
  animation: spin 0.8s linear infinite;
}

@keyframes spin {
  to {
    transform: rotate(360deg);
  }
}

 

Simple. The trick is a transparent-ish border all around, with one edge fully colored. Rotate it, and you get the illusion of something chasing itself.

But let's make it sleeker. A gradient border gives it more depth:

 

<div class="spinner-gradient"></div>

 

.spinner-gradient {
  width: 48px;
  height: 48px;
  border-radius: 50%;
  background: conic-gradient(from 0deg, transparent 0%, #667eea 100%);
  mask: radial-gradient(farthest-side, transparent calc(100% - 5px), #000 calc(100% - 5px));
  -webkit-mask: radial-gradient(farthest-side, transparent calc(100% - 5px), #000 calc(100% - 5px));
  animation: spin 1s linear infinite;
}

 

The conic-gradient creates a smooth fade from transparent to solid as it goes around the circle. The mask cuts out the center, leaving only the ring. No harsh edge where the spinner "starts," just a continuous gradient tail.

For even more visual interest, a double ring with counter-rotation:

 

<div class="spinner-double"></div>

 

.spinner-double {
  width: 48px;
  height: 48px;
  border: 3px solid transparent;
  border-top-color: #667eea;
  border-bottom-color: #667eea;
  border-radius: 50%;
  animation: spin 1s linear infinite;
  position: relative;
}

.spinner-double::before {
  content: '';
  position: absolute;
  inset: 5px;
  border: 3px solid transparent;
  border-left-color: rgba(102, 126, 234, 0.4);
  border-right-color: rgba(102, 126, 234, 0.4);
  border-radius: 50%;
  animation: spin 0.6s linear infinite reverse;
}

 

Two rings spinning in opposite directions at different speeds. The outer ring rotates at 1 second, the inner at 0.6 seconds in reverse. Creates visual complexity without being loud. The inset: 5px positions the inner ring nicely inside the outer one.

Level 3: The Pulse

No rotation, just breathing. Expansion and contraction.

 

<div class="pulse"></div>

 

.pulse {
  width: 20px;
  height: 20px;
  background: #667eea;
  border-radius: 50%;

@keyframes pulse {
  0%, 100% {
    transform: scale(1);
    opacity: 1;
  }
  50% {
    transform: scale(1.5);
    opacity: 0.4;
  }
}

 

The dot grows to 1.5x its size while fading, then shrinks back. The ease-in-out timing makes the motion feel organic, like breathing.

For a ripple effect that feels more alive:

 

<div class="pulse-ripple"></div>

 

.pulse-ripple {
  width: 20px;
  height: 20px;
  background: #667eea;
  border-radius: 50%;
  position: relative;
}

.pulse-ripple::before,
.pulse-ripple::after {
  content: '';
  position: absolute;
  inset: 0;
  border-radius: 50%;
  background: inherit;
  animation: ripple 1.5s ease-out infinite;
}

.pulse-ripple::after {
  animation-delay: 0.5s;
}

@keyframes ripple {
  0% {
    transform: scale(1);
    opacity: 0.8;
  }
  100% {
    transform: scale(2.5);
    opacity: 0;
  }
}

 

Waves expanding outward from a central point. Two pseudo-elements, staggered by 0.5 seconds, create overlapping ripples. The ease-out timing makes the ripple start fast and slow down as it fades, like a real wave dissipating. Feels like a heartbeat or a radar ping.

.dots-squish span:nth-child(2) {

.dots-squish span:nth-child(3) {

@keyframes squish {
  0% {
    transform: translateY(0) scaleX(1) scaleY(1);
  }
  30% {

  50% {
    transform: translateY(0) scaleX(1.2) scaleY(0.8);
  }
  70% {

  }
  100% {
    transform: translateY(0) scaleX(1) scaleY(1);
  }
}

 

The dots stretch vertically when moving up (scaleX(0.85) scaleY(1.15)), then squash horizontally when landing (scaleX(1.2) scaleY(0.8)). There's even a small secondary bounce at 70%. Small detail, big difference. They feel like they have weight now.

The gradient adds polish. align-items: flex-end anchors them to the bottom so the squash looks like it's hitting a surface.

Level 5: The Morphing Shape

A single shape that transforms into other shapes. No spinning, just fluid change.

 

<div class="morph"></div>

 

.morph {
  width: 44px;
  height: 44px;
  background: linear-gradient(135deg, #f093fb 0%, #f5576c 100%);
  animation: morph 2s ease-in-out infinite;
}

@keyframes morph {
  0%, 100% {
    border-radius: 50%;
    transform: rotate(0deg);
  }
  25% {
    border-radius: 50% 0 50% 0;
    transform: rotate(45deg);
  }
  50% {
    border-radius: 10%;
    transform: rotate(90deg);
  }
  75% {
    border-radius: 0 50% 0 50%;
    transform: rotate(135deg);
  }
}

 

Circle to star-ish to square to star-ish to circle. The rotation keeps it flowing. Each state feels connected to the next.

For something more organic:

 

<div class="blob"></div>

 

.blob {
  width: 50px;
  height: 50px;
  background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
  animation: blob 4s ease-in-out infinite;
}

@keyframes blob {
  0%, 100% {
    border-radius: 60% 40% 30% 70% / 60% 30% 70% 40%;
  }
  25% {
    border-radius: 30% 60% 70% 40% / 50% 60% 30% 60%;
  }
  50% {
    border-radius: 50% 60% 30% 60% / 30% 40% 70% 60%;
  }
  75% {
    border-radius: 60% 30% 60% 40% / 70% 50% 40% 60%;
  }
}

 

Eight-value border-radius creates asymmetric curves. The syntax is top-left top-right bottom-right bottom-left / top-left top-right bottom-right bottom-left for horizontal and vertical radii separately. The shape constantly shifts like a lava lamp blob. Hypnotic without being distracting.

Level 6: The Snake Ring (SVG)

When CSS borders aren't enough, SVG stroke animations give you more control.

 

<svg class="snake" width="50" height="50" viewBox="0 0 50 50">
  <circle
    cx="25"
    cy="25"
    r="20"
    fill="none"
    stroke="url(#snake-gradient)"
    stroke-width="4"
    stroke-linecap="round"
  />
  <defs>
    <linearGradient id="snake-gradient" x1="0%" y1="0%" x2="100%" y2="0%">
      <stop offset="0%" stop-color="#667eea" />
      <stop offset="100%" stop-color="#764ba2" />
    </linearGradient>
  </defs>
</svg>

 

.snake {
  animation: spin 2s linear infinite;
}

.snake circle {
  stroke-dasharray: 1, 200;
  stroke-dashoffset: 0;
  animation: snake 1.5s ease-in-out infinite;
}

@keyframes snake {
  0% {
    stroke-dasharray: 1, 200;
    stroke-dashoffset: 0;
  }
  50% {
    stroke-dasharray: 89, 200;
    stroke-dashoffset: -35;
  }
  100% {
    stroke-dasharray: 89, 200;
    stroke-dashoffset: -124;
  }
}

 

Here's how it works: stroke-dasharray controls how much of the stroke is visible. 1, 200 means 1 unit drawn, 200 units gap. As the first number increases to 89, more of the circle appears. The stroke-dashoffset shifts where the stroke starts, creating the chase effect.

Combined with the 2-second rotation on the parent, you get a snake chasing its tail. The gradient adds visual polish. stroke-linecap: round softens the ends so it doesn't look like a cut-off chunk.

AI Chats Changed Everything

Traditional interfaces had clear start and end points. Click button, wait, see result. Done.

AI chat interfaces don't work like that. You send a message, and the response streams in word by word. What do you show while the first token is being generated? What about between tokens? How do you indicate the AI is "thinking" versus "speaking"?

The old spinner doesn't quite fit anymore. Showing a spinner while text streams in feels disconnected. The text is already there, why is something still spinning?

Most AI interfaces now use a hybrid approach. Three phases, three different indicators.

Phase 1: Thinking

Before any text appears, show something subtle:

 

<div class="ai-thinking">
  <span></span>
  <span></span>

The Timing That Actually Matters

Animation duration isn't just about making things look nice. Different speeds communicate different things.
Fast (under 300ms): Feels responsive, snappy. Good for UI feedback.
Medium (300ms to 1s): Feels deliberate. Good for content loading.
Slow (over 1s): Feels like a process. Good for complex operations.

The easing function matters too:

linear: Constant speed. Feels mechanical, reliable. Good for spinners that just need to go round and round.
ease-in: Starts slow, speeds up. Feels like building momentum.
ease-out: Starts fast, slows down. Feels like settling into place.
ease-in-out: Slow, fast, slow. Feels organic, breathing.

There's also something called the "uncanny valley" of animation timing. An animation at 0.7 seconds feels weird, not quite fast and not quite slow. It sits in a strange middle ground. Either commit to snappy (under 0.4s) or deliberate (over 1s), or have a good reason for the middle ground.

When JavaScript Enters the Picture

Pure CSS handles most loader needs, but sometimes you want more control. Maybe the loader should only appear after a delay. Maybe it should disappear gracefully.

class LoadingState {
  constructor(element, options = {}) {
    this.element = element;
    this.delay = options.delay || 200;
    this.minDisplay = options.minDisplay || 400;
    this.timer = null;
    this.showTime = null;
  }

  show() {
    this.timer = setTimeout(() => {
      this.element.classList.add('loading');
      this.showTime = Date.now();
    }, this.delay);
  }

  hide() {
    clearTimeout(this.timer);
    
    if (!this.showTime) {
      return;
    }

    const elapsed = Date.now() - this.showTime;
    const remaining = Math.max(0, this.minDisplay - elapsed);

    setTimeout(() => {
      this.element.classList.remove('loading');
      this.showTime = null;
    }, remaining);
  }
}

 

This handles two common problems:

  1. The loader won't flash for fast operations (200ms delay before showing)
  2. The loader won't disappear too quickly once shown (minimum 400ms display)

That minimum display time prevents a jarring flash if the operation finishes right after the loader appears. If users see a loader at all, they should see it for long enough to register what it was.

The Invisible Best Practice

The best loader is one users barely notice. It's there when needed, gone when not, and never draws attention to itself. It doesn't spin aggressively. It doesn't bounce too high. It doesn't shimmer too brightly.

Think of it like a good waiter at a restaurant. You know they're there, they respond when you need them, but they don't hover over your table asking if everything's okay every thirty seconds.

A loading state should feel like part of the interface, not an interruption to it. The animation should match the overall feel of your design. A playful app can have playful loaders. A serious enterprise tool probably wants something more muted.

Pick the right level of complexity for the wait time. A 500ms load doesn't need falling tetris pieces. A 30-second splash screen shouldn't be a single spinning dot.

And always, always, provide a way out. If something takes too long, users should be able to cancel. If something fails, they should know. The loader is a promise, and broken promises are worse than no promise at all.

The next time you're waiting for something to load, take a second to watch the animation. Notice how it moves, how fast it goes, what it makes you feel. Someone thought about all of that. And now you can be that someone.

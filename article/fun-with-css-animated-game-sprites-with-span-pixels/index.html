Fun with CSS: animated game sprites with span pixels

by
Jos van Panhuis

A short while back we had an internal CSS challenge in our front-end guild where the goal was “to create a smooth shape transition while also changing its background color”. Pretty straightforward, but this allowed people to get creative with solutions.

#Sprite
#Game
#CSS

While I initially created a more generic solution that met both requirements, I also had something else in mind to “transition the background color” using only CSS. After a few iterations, the result was this:

If you think that this seems a bit excessive for the challenge, you’re right!

In this article I will go through the thought processes and approach to get to the result of the above gif.

If you want to see the above in action for yourself, or want to dive straight into the code to see how it was made, check out the CodePen page. 

Please note that this is all in good fun and in no way offers production worthy code. But it’s a fun experiment nonetheless to use CSS in a different way!

First setup: create spans that acts as pixels


The challenge triggered me to think about pixels changing color values. With my love for retro video games, thinking about pixels triggered me to think about recreating a game’s sprite in HTML, where each pixel was a span that could change color. 

Fun idea, but I wasn’t going to hand-draw a sprite pixel by pixel using span elements with background colors. 
Doing a Google search on “convert image to pixel data” resulted in finding a page called “Pixel Values Extractor”, its description is “Extract pixel values from images [which will] be converted to numerical [RGB] values”.

Let’s say we upload the above 3x1 pixel image that contains a red (#FF0000), green (#00FF00), and blue (#0000FF) pixel and we convert that image to RGB pixel values with the above tool. The outcome will be:
255 0 0 0 255 0 0 0 255

The first 3 digits represent the RGB values of the red pixel, the next 3 digits the green pixel, and the last 3 digits the blue pixel. This data is a perfect base for us to work on, and set the pixel color value in the html on a span element like this:

<span style="--color: rgb(255, 0, 0);"></span>
<span style="--color: rgb(0, 255, 0);"></span>
<span style="--color: rgb(0, 0, 255);"></span>

Creating a sprite with a grid of span-pixels

Now that we can generate spans with colors based on an image, we need a nice image to work with.
I’m a big fan of SNES classics, so I went with this sprite of the playable character from Contra 3: The Alien Wars.

Running this image through the Pixel Values Extractor tool, we get a whole bunch of numbers as seen below. By looking at the code we can also recognize the (distorted) shape of the sprite:

Next thing to do is to search and replace each pair of 3 digits into a span with an RGB color.

VS Code has a handy regex option for search.
By inputting \b(\d+)\s(\d+)\s(\d+)\b as the search query and replacing all results with <span style="--color: rgb($1 $2 $3);"></span>, we’ll get the HTML that we need.


Now that we have our HTML with spans we can start working on the CSS.
Let’s create a new Pen in CodePen and paste the HTML in. Add a wrapper div with class .container so we have a container for our span pixels.

Configure the CSS to use the SCSS preprocessor so we can have variables and do calculations.
For our CSS we start by setting some SCSS variables for the pixel & grid data, the sprite that I used was 40px wide and 40px high.

$pixel-size: 10;
$pixel-rows: 40;
$pixels-per-row: 40;

Next thing to do is to add styling for the .container and span elements to make our sprite visible.

.container {
  display: flex;
  flex-wrap: wrap;
  width: #{$pixel-size * $pixels-per-row}px;
  height: #{$pixel-size * $pixel-rows}px;
  margin: 0 auto;
  margin-top: calc(50vh - #{($pixel-size * $pixel-rows) / 2}px);
}

span {
  width: #{$pixel-size}px;
  height: #{$pixel-size}px;
  background: var(--color);
}


With this our container is centered both horizontally and vertically on the page and has the exact width and height based on the pixel size + amount of pixels. Each span now has a fixed width and height with a background color. 

If we look at the output, it should look like this:

As you can see, the transparent pixels of the sprite have been transformed into black pixels. We don’t want this so we can search and replace all <span style="--color: rgb(0 0 0);"></span> to become <span></span>. This will also save us a lot of HTML characters which we’ll need later-on for performance reasons. (If your sprite has actual pure-black pixels in it, you should output the image data as RGBA instead of RGB, then remove the transparent pixels for performance reasons)

And there you have it! A sprite built entirely with CSS and without any actual images in our code.
But let’s take it to the next level in the next chapters.

Setting up for an animated version

Remember the early RGB image with this code?

<span style="--color: rgb(255, 0, 0);"></span>
<span style="--color: rgb(0, 255, 0);"></span>
<span style="--color: rgb(0, 0, 255);"></span>

The beauty of setting CSS variables inside the styling of a span is that you can use this in your CSS. This is where I had the idea to combine multiple CSS variables into a single span and then loop over these using a CSS animation.

<span style="
--color1: rgb(255, 0, 0); 
--color2: rgb(0, 255, 0); 
--color3: rgb(0, 0, 255);
"></span>

With this setup we can add an animation that has 3 steps like this:

span {
  animation: RGB 1s steps(1) infinite;
}

@keyframes RGB {
  0% {
    background: var(--color1); 
  }
  
  33% {
    background: var(--color2); 
  }

  66% {
    background: var(--color3); 
  }
}

To break down the animation property’s value:

  • RGB is the name of the keyframe animation that should be used
  • 1s (one second) is the length of the animation
  • steps(1) determines the amount of steps that should be taken between each step (0%, 33%, 66%) of the animation. Setting it to use 1 step will make sure that there is no gradual transition of colors between each animation step, but instead colors will change instantly.
  • infinite will make the animation loop

If we take a look at the output of this in the browser, we can see that the red, green and blue pixels nicely animate without any gradual color change.

 

So yay, that works! Now we can work on actually implementing different animations for the game sprite.

Before we do that however we also need something to trigger the animations. What I did was add a button before the span elements inside the container like this:

<div class="container">
  <button>Hover me</button>

  <span></span>
  <span></span>
  ...
</div>

With that setup, we can add a hover selector to the button, then select all span elements that come after the button and adjust the styling of the spans to trigger an animation. (If you wish you could also do something similar with a radio button group where you select all spans after a specific selected radio button)

button:hover ~ span {
  animation: RGB 1s steps(1) infinite;
}

Adding animations for the game sprite

In order to create animations for our sprite, we’ll need a few things:

  1. the actual sprites, frame by frame.
  2. align all sprites with each other so the movement isn’t choppy
  3. run all sprites through the online tool and collect the pixel data
  4. merge the pixel data for all frames into a single file, where each span holds the necessary colors for all frames
  5. finish up

Getting the sprites, frame by frame

The best place (to my knowledge) to get sprites for games is https://www.spriters-resource.com/. It contains a vast database of sprites for games on any kind of system.

For this example I took the spritesheet from https://www.spriters-resource.com/snes/contra3/sheet/23780/
Save the spritesheet to your computer and use any program of your choice to cut out the individual frames of an animation. In my case I used Photoshop.

Let’s take the walking animation as an example.

Each of these frames were cut up into separate files and called walk1.png, walk2.png, etc. Don’t worry too much about the different dimensions that each frame will have, we’ll take care of that in the next step.

Repeat this process for all animations that you wish to implement (I went for the “walk”, “shoot”, “jump” and “climb” animations for my showcase).

Aligning the sprites

In order to not make the animations of the character choppy and all over the place, we need to determine what our “canvas size” will be, then align all frames inside that canvas.

Look at the dimensions of all your frames and see which once has the biggest width and/or height.
In my case 1 frame from the “shoot” animation was 40px by 40px. Another frame from the “climb” animation was 16px by 48px.

Having a canvas with equal width and height will make it easier to work with all animations, but is also a requirement for the setup that we have. I went with a canvas that is 50px by 50px so all frames will fit in that. This also means that our .container element will take 50 pixel rows and 50 pixels per row. Creating a large(r) canvas could have impact on browser performance though, so keep that in mind.

Create a new file with your determined canvas size and load all frames into this file as separate layers.
Determine a baseline for your alignment, which you will use to align other frames.

See that thin blue vertical line in the middle of the image? That’s a Photoshop guide line that I placed on the right side of the character’s face from the “idle” frame. For other frames I will either use that (in the “run” animation) or something else like the position of the feet (in the “shoot” animation) as my baseline.

Once aligned, save each frame as a final version as separate files that you will use in the next step.

Running all frames through the Pixel Values Extractor tool

Now that we have each frame aligned and as separate files, we can load each file into the Pixel Values Extractor tool.

It’s a bit of a tedious job, but make sure you copy the output of the tool for each image into a separate file and save that file with a clear name (i.e.: walk1.txt) so you know which frame data that file holds.

I said it in the intro and I’ll say it again, this was just a fun experiment and doing these manual code adjustments for many frames can be tedious/bug prone. 
If this were to be something more serious or something that was used in production, automating this process would become an important part to make sure that your life becomes easier, to prevent errors in the code and to make it scalable.

Once you’ve converted all images to pixel data in separate files, do a search and replace in each file with the regex that I provided before:
\b(\d+)\s(\d+)\s(\d+)\b

This time however for the replace part, create a unique name for your CSS variable based on the frame name, like this:
<span style="--walk1: rgb($1 $2 $3);"></span>
and
<span style="--walk2: rgb($1 $2 $3);"></span>
etc.

Do not clean up the black pixels (i.e. <span style="—walk1: rgb(0 0 0)"></span>) yet however, we still need those for the next part!

Merge the data for all frames into a single file

This is the 2nd part of the tedious job.

For this to work you’re going to have to use an IDE that allows you to select multiple instances of a certain text inside a file. VS Code for example has this neat feature with the VS Code command “select all occurrences of find match”.

Select the name of your CSS variable (like “--walk1:”) and then select all instances of that. It should look like this:

Next thing you need to do is carefully expand the selection to the right until you reach the semicolon. Be aware that if you just use “shift + right arrow” multiple times, you’ll have a bad match as some rgb values are longer than others:

Be sure to use “shift + ctrl + right arrow” to select entire numbers instead, while moving to the right:

Now that you’ve made the right selection, copy it to your clipboard and paste it into your “base” file that contains a grid of spans. In my case for my “base” file I had a grid of spans with the “idle” frame as my first CSS variable.

Perform the same selection process for your “base” file. 
Select all instances of the “--idle" CSS variable for example, put those on a new line, then start a new line and paste in the “--walk1” CSS variables that you copied from your other file.

Repeat this process for all frames until you have spans that look something like this:

<span style="
--idle1: rgb(96, 72, 56);
--walk1: rgb(24, 112, 136);
--walk2: rgb(24, 112, 136);
--walk3: rgb(24, 112, 136);
--walk4: rgb(96, 72, 56);
--shoot1: rgb(128, 104, 88);
--shoot2: rgb(128, 104, 88);
--shoot3: rgb(128, 104, 88);
--climb1: rgb(128, 104, 88);
--climb2: rgb(128, 104, 88);
--climb3: rgb(128, 104, 88);
--climb4: rgb(128, 104, 88);
--jump1: rgb(48, 32, 16);
--jump2: rgb(120, 40, 8);
--jump3: rgb(120, 40, 8);
--jump4: rgb(0, 0, 0);
--jump5: rgb(0, 0, 0);
--jump6: rgb(120, 40, 8);
--jump7: rgb(80, 184, 192);
"></span>

By now you’ll have noticed that your IDE and machine are having a hard time processing all the characters. You can easily have over 10.000 lines in your code once you are done and if you have multiple animations.

Let’s improve performance a bit and round this up.

Finishing up

In order to improve performance a bit, search for all instances of “rgb(0, 0, 0)” and remove those lines. It’s okay that this will remove the CSS variable as well. That should easily cut the amount of lines your code has in half.

Performance will never be great though, as the browser is simply not intended for animations like these. But hey, it’s a fun exercise so to hell with performance!

Now that we have all the required pixel data in our spans, it’s time to implement multiple buttons that will trigger the different kinds of animations.

In my example I have a static “idle” frame (although you could also have an “idle” animation if your sprite needs that) which is used by default in my spans:

span {
  width: #{$pixel-size}px;
  height: #{$pixel-size}px;
  background: var(--idle1);
}

I’ve added 4 buttons that each trigger an animation when hovered:

button {
  &[walk]:hover ~ span {
    animation: walk 0.6s steps(1) infinite;
  }

  &[shoot]:hover ~ span {
    animation: shoot 0.2s steps(1) infinite;
  }

  &[jump]:hover ~ span {
    animation: jump 1.2s steps(1) forwards;
  }
  
  &[climb]:hover ~ span {
    animation: climb 0.6s steps(1) infinite;
  }
}

Now add the various keyframe animations. See how many frames your animation has and then adjust the percentage of each step based on that like this:

@keyframes walk {
  0% { background: var(--walk1); }
  25% { background: var(--walk2); }
  50% { background: var(--walk3); }
  75% { background: var(--walk4); }
}
@keyframes shoot {
  0% { background: var(--shoot1); }
  33% { background: var(--shoot2); }
  66% { background: var(--shoot3); }
}
@keyframes jump {
  0% { background: var(--jump1); }
  12% { background: var(--jump2); }
  25% { background: var(--jump3); }
  50% { background: var(--jump4); }
  62% { background: var(--jump5); }
  75% { background: var(--jump6); }
  87% { background: var(--jump7); }
}
@keyframes climb {
  0% { background: var(--climb1); }
  25% { background: var(--climb2); }
  50% { background: var(--climb3); }
  75% { background: var(--climb4); }
}

And there you have it!

Flutter

On December 4, 2018, Google announced the first stable release of the open source framework Flutter for the Dart programming language. With Flutter, it is currently possible to build apps for both Android and iOS. In this article I will explain how Flutter works and what exactly Google's plans are with Flutter.

The first version of Flutter, called “Sky” worked only on Android and was presented in 2015 at the Dart Developer summit. Google started stripping out the Chrome Browser. What remained was a rendering engine that was over twenty times faster than the current Chrome Browser. This renderEngine is used to render the app on the screen. Next Google experimented with Javascript. It soon became clear that this did not work and the choice was made for the programming language Dart. Dart is now the language with which a Flutter app can be built. Dart is perhaps the only mainstream language that supports both just-in-time and a-head-of-time compilation. By supporting both forms of compilation, you have the benefits of both worlds. With just-in-time compilation, Dart ensures that the development of a Flutter project can proceed very quickly. This is because the changes you make during development are immediately visible in your app. When we release an app-release, then a release with a-head-of-time compilation will be released. This ensures for fast startup times and high performance of the app. The Flutter engine is primarily written in C++. That in turn makes use of Google's Skia library that takes care of the rendering on the various platforms.

How to get started with Flutter. 

The installation of Flutter is relatively simple.  You go to the website https://flutter.dev and follow the installation guide. Flutter can be installed on Windows, macOS and Linux.  The Flutter and Dart plugins are available for common IDEs, such as Android Studio, IntelliJ and Visual Studio Code. Installing and getting started with Flutter and Dart is easy. Therefore, as a developer, you will soon be able to get by with Dart.

Framework 

An app in Flutter consists of widgets. By composing widgets, you can create new widgets. Rendering an app on the screen is done at up to 120 fps. That means the app feels super smooth. How is this possible? Rendering the app on the screen is done in Flutter with three different trees. One for the widgets, one for the elements and one for the render objects.

The render tree takes care of the layout and draws the app on the screen. These are expensive operations that take a lot of time. It is therefore convenient to do this as little as possible and recycle and cache as much as possible of what is on the screen. The recycling and caching of render objects is done in the Element tree. The Widget tree is immutable therefore the Element tree is the 'glue' between the immutable widgets and the mutable render objects. The element tree is actually very good at comparing widget objects and render objects and adapts the existing render objects as much as possible. 

Widgets

You build an app in Flutter with widgets. In Flutter there are two types of widgets, stateless widgets and stateful widgets. A stateless widget is an immutable configuration, a blueprint for an element. A stateless widget does not need to keep track of its state and only has to deal with the data that was initially given to the widget during construction. This data will not change anymore.

The parent widget actually determines the state of the stateless widget. Stateful widgets are dynamic and do contain a state. Stateful widgets allow us to change the content. This can happen when the user presses something, in response to an asynchronous call or when there is a state change in the app. A Stateful widget extends the StatefulWidget class. Like Stateless, a Stateful widget can also expect construction parameters that set the initial state. The StatefulWidget class contains a function createState which we need to override. In the createState function we need to return a new state of the widget. The state we return must be an extension of the State class. This State class contains a build function that returns the final widget. By changing the state in the setState function we inform Flutter that a state change has taken place. Flutter will execute the build function to create a new widget. To make this theory a bit clearer below are two examples of a stateless widget and a stateful widget.

Using stateless widget 

The first widget I use is the Raw MaterialButton. In addition to some parameters, such as color and shape, almost every widget has the ability to add another widget in the form of a child. In this case, I am adding the Row widget, because I would like to add an icon and a text to my button. The Row widget then takes up all the available space. If I do not configure anything else on the Row widget, this would mean that a button would appear over the entire screen. This can be prevented by setting MainAxisSize of the Row widget.  The beauty of a Row Widget is of course that it can contain multiple children, so I can add both an Icon widget and a Text widget. After adding Icon widget and the Text widget, the widgets are facing each other. By putting a SizedBox widget between both widgets, it ensures that there is 10 pixels space between the icon and the text.

 

With this example, it has become clear how to create a stateless widget and how to make a new widget from multiple widgets. 

Using a Stateful Widget 

We also want to be able to update the value of, say, a text within an app or replace widgets with other widgets. We do this by using stateful widgets. In the example below we extend MyHomePage class of StatefulWidget. The StatefulWidget class contains the createState method that we need to override. The createState function always returns a new state. In this case, we are returning the _MyHome PageState. The _MyHomePageState is again an extension of class State and contains the build function. The build function returns the widget. In the case that the state of the widget is modified in the setState function, Flutter will call the build function again to get a new widget containing the modified value.

 

App development 

Fortunately, it is not necessary to build all widgets yourself in Flutter. In fact, because Flutter makes full use of the principles of Material Design, it is very easy to build a beautiful and well-functioning app.  However, if you want a specific button, switch or table layout from iOS, there are the Cupertino widgets that contain all the elements pixel perfect from iOS. Many widgets can be found in the Material Design widgets and often form the basis of an app. The Material Design department of Google uses Flutter as a playground for their latest ideas.  Therefore the Material Design widgets are very extensive. With Material Design, you can build an app that feels comfortable for both platforms. It doesn't mean that an app is going to look like a Google app. The beauty of Material Design is that you have full control over how your app will look. 

There are many different types of widgets. For example, there is a GestureDetector widget. If we wrap a widget with the GestureDetector, then Tap, LongPress, Drag, etc. is detected in the GestureDetectorWidget.

One of my favorite Widgets is the Hero widget. With the Hero widget, you give the user insight into where he came from and where he is navigating to. Say you have a list of photos. By placing the photo in a Hero widget with an ID and on the details page placing the same photo in a Hero widget with the same ID, Flutter will animate the image to the new location. When you navigate back to the list, the picture from the detail page will animate back into the list. Super cool!

This is one of the many features that comes standard in Flutter. By using the default widgets, a nice app can already be built.

Stateful hot reload 

Flutter allows you to develop really fast. Flutter is able to make code changes "on the fly" to the app without rebuilding or restarting the app and without the app losing its state. While coding the app you can see the effect of the changes immediately. If you save your changes, then your changes are pushed directly to the simulator. So you can literally see your app being created on the simulator while you are coding your app. Code changes, such as changing the logic of the app, are also visible immediately. The best part is that the state of the app is preserved. After saving a change you will not have to go through a login process or fill a shopping cart to create the test case where the bug occurred to see if the code change fixes it. The state of the app is preserved.  

Flutter inspector 

Debugging an app is always an important part of the development process.  Flutter offers good support for this as well, in the form of an excellent debugger and the Flutter inspector. With the Flutter inspector you can analyze the entire structure of your app.

Packages 

To gain access to the camera, for example, you can use packages. Packages can be found at https://pub.dev/flutter and can easily be added to an app by adding the dependency to the pubspec.yaml file. Many packages have been created by the Flutter team. These packages are of high quality and contain good documentation. In case you cannot find certain functionality in one of the packages, you can write your own packages. However, keep in mind that as soon as you write a package and want to publish it for both platforms, you must write a package that supports both platforms. 

Flutter on the web

During Google IO 2019, the preview project "Flutter for the Web", previously called "Hummingbird", was presented.  With "Flutter for the Web" a Flutter app can be compiled not only to iOS and Android, but also to the web. It doesn't stop here with Flutter. Google's plan is to make Flutter apps run anywhere including Windows, macOS, Apple TV, Android TV you name it. So "build once, run anywhere". 


 

 

Flare

During the introduction of Flutter, the Flare framework was also introduced. With Flare we can, with the help of the Flare web tool, create a 2D Animated Vector Graphics. With Flare we can create animations, which we can easily integrate into our Flutter project. The nice thing about Flare is that it is completely open source. The content that is created is also open source by default. The advantage of this is that many animations are available for free and can be used in your app. If you want to keep animations for yourself, then a small amount must be paid. In the example above the bear follows the cursor. If the password is entered correctly and the "Sign In" button is pressed, the bear will start smiling. If the password is incorrect, the bear will shake its head and say "no". Flare offers the possibility to capture multiple states in their animation and then animate from state 1 to state 2. Or to animate from state 1 to state 6. 

 

CodeMagic 

In addition to Flare, the CI/CD tool CodeMagic has been introduced. With CodeMagic, you can set up a complete build pipeline with just a few clicks. As soon as CodeMagic gets access to read your repositories on GitHub, Bit bucket or GitLab, CodeMagic will search for all Flutter repositories your account has access to. After finding the Flutter repositories you will be given the option to configure them for analyzing, building, testing and finally publishing the app in AppStore and/or PlayStore. 

YouTube 

In addition to a well-documented website, Flutter also has a very nice YouTube channel. "The Boring Flutter Development Show" is definitely recommended. In this series of videos, the Flutter team shows -with great humor- how to build an app in Flutter.  Also the series "Widget of the week" is definitely worth watching. This way you will discover what widgets there are and what they are used for.

The Future 

Android is built on the Linux kernel. Initially, Android was developed for digital cameras. The core of Android is actually not specialized in what we all expect from a phone these days. This is often the reason why hardware in Android phones performs less than actually expected. Android has OEM software, kernel and drivers that are configured in such a way that it is not easy to just perform a kernel update. You are depending on your phone vendor for receiving Android updates. Since 2016, Google has been working on a new OS called Fuchsia OS.

Fuchsia OS specializes in running on as many different devices as possible. From refrigerator to traffic light and from speaker to phone. With this, Google is trying to make one OS for everything. Fuchsia OS is built in such a way that an update can easily be pushed by Google without the intervention of an OEM. It is not yet clear if Fuchsia OS will ever replace Android. Building an app for Fuchsia is done with Flutter.

 

Conclusion 
 

Is Flutter the future of mobile app development?  

Because of the good documentation and the plugins that are largely maintained by the Flutter team, this is certainly a framework that we will be hearing a lot about. Not only the ease with which you can build a nice interface, but also the tools you have at your disposal to build an app, makes Flutter a nice framework. By default, a lot is available in the framework, which often allows you to build a nice app without third party libraries. Flutter is still fairly new, so there are few best practices. There are also still numerous bugs to be found. It is a living community where questions can be asked and you also get quick answers. If you want to build an app, I would definitely recommend you to take a look at the possibilities of Flutter.  Flutter is definitely not a one-day-fly and is worth considering if you have the choice to build a new app, even if it is for only one platform.

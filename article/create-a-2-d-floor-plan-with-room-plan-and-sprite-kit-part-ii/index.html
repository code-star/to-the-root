Create a 2D floor plan with RoomPlan and SpriteKit - Part II

by
Dennis van Oosten

This is the second part of a two-part tutorial. In Part I, we created a RoomPlan setup in SwiftUI. We created a welcome screen and allowed the user to scan their room. This part will focus on turning the output of the scan into a 2D floor plan. We will use SpriteKit to draw the surfaces and objects onto the screen.

From scan to 2D floor plan

We’re going to create the floor plan in SpriteKit: Apple’s general-purpose framework for drawing shapes, particles, text, images, and video in two dimensions. This is ideal for creating a floor plan, since it provides all the tools for drawing 2D graphics, such as the walls and doors of our scanned room.

Creating a SpriteKit scene

Create a new Swift file: FloorPlanScene.

Start by importing RoomPlan and SpriteKit and create a class FloorPlanScene that inherits from SKScene.

import RoomPlan
import SpriteKit

class FloorPlanScene: SKScene {
}

In SpriteKit, an SKSceneobject represents a scene of content. A scene is the root node in a tree of SpriteKit nodes (SKNode) and it organizes all of the active SpriteKit content.

You might have noticed Xcode throws an error at you. To resolve this, you can use Xcode’s suggestion and add the required initializer to the class:

required init?(coder aDecoder: NSCoder) {
    fatalError("init(coder:) has not been implemented")
}

We need a way to transition to this scene. Right now, nothing happens when we click the button ‘View 2D floor plan’. In RoomCaptureScanView, add a new @State variable:

@State private var isShowingFloorPlan = false

We can change this value when the user taps the button. Change the else statement of the button to set isShowingFloorPlan to true.

Button(isScanning ? "Done" : "View 2D floor plan") {
    if isScanning {
        stopSession()
    } else {
        isShowingFloorPlan = true
    }
}

We’re going to present the floor plan scene as a full screen cover. Add the following underneath the onAppear(perform:)method:

.fullScreenCover(isPresented: $isShowingFloorPlan) {
    SpriteView(scene: FloorPlanScene(capturedRoom: model.finalRoom!))
        .ignoresSafeArea()
}

fullScreenCover(isPresented:) will present a full screen cover when isPresented is true. When the user taps the button, isShowingFloorPlan will be set to true, hence the full screen cover will be presented.

The content of the cover is a SpriteView. This is a special SwiftUI view to present SpriteKit content. You’ll get an error however, because you have to import _SpriteKit_SwiftUI in order to use SpriteView.

import _SpriteKit_SwiftUI

The SpriteView accepts an SKScene as a parameter. We initialize our FloorPlanScene here and pass in the finalRoom from our model. It’s an optional property, but since we know we’ll have our room scanned by now, we’ll force unwrap it.

The ignoresSafeArea() modifier ensures we don’t get ugly bars around our view.

Run the app and scan a room. If you tap the button you should be presented with a grey screen. This is the default backgroundColor of our SpriteKit scene.

CapturedRoom

Before drawing any surfaces or objects in the SpriteKit scene, let’s examine the CapturedRoom object. This is the result of out RoomPlan scan and contains all information we need to create a floor plan. It contains arrays for several types of surfaces (CapturedRoom.Surface) and an array that contains all objects (CapturedRoom.Object). The surface and object structures both contain the following properties:

Identifier

A UUID that uniquely identifies every surface or object.

Category

This tells us what type of surface or object we’re dealing with. For surfaces, this is either a door, opening, wall or window. For objects, RoomPlan classifies the following objects: bathtub, bed, chair, dishwasher, fireplace, oven, refridgerator, sink, sofa, stairs, storage, stove, table, television, toilet, washerDryer.

Confidence

How sure RoomPlan is about the category of the surface. This is either high, medium or low.

Transform

A 4x4 matrix (4 columns and 4 rows of numbers) that stores information about position and rotation.

Dimensions

A vector of three numbers that defines the bounding box that contains the surface or object.

Setting the scene

In FloorPlanScene, add two arrays to the top of the class. These will store our scanned surfaces and objects.

private let surfaces: [CapturedRoom.Surface]
private let objects: [CapturedRoom.Object]

Next, create the initializer for the class. We need it to provide a parameter that receives our scan result (CapturedRoom) and initialize the surfaces and objects arrays. We also need to call super.init() to complete the initializer. It expects a CGSize object that will determine the dimensions for the SKScene. I’ve set it to 1500 x 1500:

init(capturedRoom: CapturedRoom) {
    self.surfaces = capturedRoom.doors + capturedRoom.openings + capturedRoom.walls + capturedRoom.windows
    self.objects = capturedRoom.objects
        
    super.init(size: CGSize(width: 1500, height: 1500))
}

To set the scene up properly, set a few additional properties in the initializer after the call to super.init():

self.scaleMode = .aspectFill
self.anchorPoint = CGPoint(x: 0.5, y: 0.5)
self.backgroundColor = floorPlanBackgroundColor

The scaleMode determines how to scene is scaled inside our view. aspectFill will ensure our aspect ratio is respected and the scene will not be stretched in any direction.

The anchorPoint determines the point in the view’s frame that corresponds to the scene’s origin. These are values in a range from 0.0 to 1.0. The default value is (0.0, 0.0) for the x- and y-axis respectively, which corresponds to the lower-left corner of the view’s frame rectangle. We want it to be in the center, so we set it to (0.5, 0.5).

The backgroundColor property sets the background color of the scene. Since we’ll be using this value in different places and in different files later on, create a new Swift file called DrawParameters and initialize the contant in there.

import UIKit

// Colors
let floorPlanBackgroundColor = UIColor(named: "BackgroundColor")!

Drawing the walls

Create another new Swift file to represent a surface: FloorPlanSurface. Import SpriteKit and RoomPlan again and define the class. It inherits from SKNode, since this’ll be a node in our SpriteKit node tree.

import SpriteKit
import RoomPlan

class FloorPlanSurface: SKNode {
}

Add an initializer and a property that holds the CapturedRoom.Surface:

private let capturedSurface: CapturedRoom.Surface

init(capturedSurface: CapturedRoom.Surface) {
    self.capturedSurface = capturedSurface
        
    super.init()
}

Add the required initializer as well:

required init?(coder aDecoder: NSCoder) {
    fatalError("init(coder:) has not been implemented")
}

To draw a wall, we need to:

  1. Create a path that defines the wall
  2. Create an SKShapeNode using the path to actually draw a line

To get a path, we can use the dimensions property of the CapturedRoom.Surface object. This is a vector of 3 numbers that defines the bounding box of the surface. We’re looking at the wall from the top, so we’re not interested in the height. Since it’s a surface, it also doesn’t have a depth value. The only value we need is x, which defines the length of the suface.

From the length of the wall, we can define two endpoints A and B. Create the following computed properties:

private var halfLength: CGFloat {
    return CGFloat(capturedSurface.dimensions.x) * scalingFactor / 2
}
    
private var pointA: CGPoint {
    return CGPoint(x: -halfLength, y: 0)
}
    
private var pointB: CGPoint {
    return CGPoint(x: halfLength, y: 0)
}

The position and rotation of the wall are relative to the center of the wall. Therefore, we want the center of the wall to be the anchor point of our shape. To do this, we devide the length of the wall by 2 in the halfLength property. We then use this number to calculate a pointA to the left of the center and a pointB to the right of the center.

Figure 1: calculating the two endpoints of a surface

The scalingFactor is a number that scales every element on the floor plan the same amount. The numbers from CapturedRoom are in meters. The SpriteKit scene has it’s own coordinate space and easily spans hundrerds of points from the left of an iPad screen to the right. To compensate for this difference, we scale up our surfaces and objects so they will be more than tiny specs on the screen.

Add the scalingFactor constant to DrawParameters.swift. 200 seems to work fine for me.

// Universal scaling factor
let scalingFactor: CGFloat = 200

Next, in FloorPlanSurface, add a function that creates a path using two points:

private func createPath(from pointA: CGPoint, to pointB: CGPoint) -> CGMutablePath {
    let path = CGMutablePath()
    path.move(to: pointA)
    path.addLine(to: pointB)
        
    return path
}

The function takes two CGPoints as parameters and returns a path as a CGMutablePath. In the function, we first instantiate a new CGMutablePath. Then we ‘move’ our path to the starting point: pointA. Then we add a line to the endoint: pointB.

Add another function that turns the path into an SKShapeNode:

private func createShapeNode(from path: CGPath) -> SKShapeNode {
    let shapeNode = SKShapeNode(path: path)
    shapeNode.strokeColor = floorPlanSurfaceColor
    shapeNode.lineWidth = surfaceWith
        
    return shapeNode
}

First, we create a new SKShapeNode using the initializer that takes a path as an argument. Since we’re drawing a line here (instead of a filled shape), we manipulate it’s appearance by setting the strokeColor and lineWidth. Setting the lineCap to square ensures our lines will neatly connect to one another.

Define the two new constants in DrawParameters.swift:

// Colors
let floorPlanBackgroundColor = UIColor(named: "BackgroundColor")!
let floorPlanSurfaceColor = UIColor(named: "AccentColor")!

// Line widths
let surfaceWith: CGFloat = 22.0

Now, in FloorPlanSurface, create a new function to draw a wall:

private func drawWall() {
    let wallPath = createPath(from: pointA, to: pointB)
    let wallShape = createShapeNode(from: wallPath)
    wallShape.lineCap = .square

    addChild(wallShape)
}

Here we create the path using our new function and the computed properties for the two endpoints of the wall. We then use the resulting path to create a new shape.

The default lineCap is butt where Core Graphics draws the line to extend only to the exact endpoint of the path. For the walls, it looks better in my opinion to extend them a bit. square extends the line beyond the endpoint of the path for a distance equal to half the line width.

Lastly, we need to add the shape to our node tree, otherise it will not be rendered by SpriteKit.

At the end of the initializer, add a check for the category of a surface. If it’s a wall, call drawWall():

if capturedSurface.category == .wall {
    drawWall()
}

To position and rotate the wall, we use the surface’s transorm property. This is a simd_float4x4: a 4x4 transformation matrix of float values. Create a new Swift file: simd_float4x4+EulerAnglesAndPosition. In here, create an extension for the simd_float4x4 struct:

import SceneKit

extension simd_float4x4 {
    
    var eulerAngles: simd_float3 {
        simd_float3(
            x: asin(-self[2][1]),
            y: atan2(self[2][0], self[2][2]),
            z: atan2(self[0][1], self[1][1])
        )
    }

    var position: simd_float3 {
        simd_float3(
            x: self.columns.3.x,
            y: self.columns.3.y,
            z: self.columns.3.z
        )
    }
    
}

The extension contains two new variables. eulerAngles is a vector that contains the rotation information extracted from the matrix using trigonometry functions. It’s x, y and z values represent the rotation around the x-, y- and z-axis respectively. The rotation is in radians.

position is a vector as well and holds the x-, y- and z-position extracted from the matrix.

Back in FloorPlanSurface.swift, set the rotation and position of the surface in the initializer, right after the call to super.init():

let surfacePositionX = -CGFloat(capturedSurface.transform.position.x) * scalingFactor
let surfacePositionY = CGFloat(capturedSurface.transform.position.z) * scalingFactor
self.position = CGPoint(x: surfacePositionX, y: surfacePositionY)

self.zRotation = -CGFloat(capturedSurface.transform.eulerAngles.z - capturedSurface.transform.eulerAngles.y)

First, the position of the surface is set using the transform property from the extension we just created. When scanning, the x- and y-coordinates represent the width and height of objects or vertical and horizontal coordinate space. The z-coordinate represents the length or depth of objects. When looking from above, x and z represent the coordinates on the 2D floor plan. You can think of the y-axis as coming straight up from the screen, or from floor to ceiling. Because we want to create a a top-down view of the room, we can ignore the y values. The scalingFactor is applied again to scale up our floor plan accoringly.

SpriteKit uses a coordinate system where the x- and y-axis represent the horizontal and vertical axis respectively. Thus, we can rotate a node around the z-axis to rotate it clockwise or anti-clockwise. Using the eulerAngles property from the extension, we can easily get the rotation in radians from the capturedSurface's transform matrix. Why we need to subtract the rotation around the y-axis from the rotation around the z-axis is still a mystery to me but it works. If anyone know the answer, please let me know in the comments :p.

In FloorPlanScene, create a new method to draw all surfaces:

private func drawSurfaces() {
    for surface in surfaces {
        let surfaceNode = FloorPlanSurface(capturedSurface: surface)
        addChild(surfaceNode)
    }
}

Call the method at the end of the initializer:

drawSurfaces()

Run the app, scan a room and view the floor plan. You should see a 2D floor plan of your room!

You might notice though, that not everything fits on the screen. Ideally, you want to be able to zoom in and out and pan around your floor plan. To do so, we’ll add a camera to the scene.

Adding a camera

In FloorPlanScene, create a new function:

private func addCamera() {
    let cameraNode = SKCameraNode()
    addChild(cameraNode)
        
    self.camera = cameraNode
}

This creates a camera node and adds it to the scene. We also need to point the scene’s camera property to our newly created camera node.

Call the function from within the scene’s initializer:

addCamera()

To be able to zoom in and out and to pan around the scene, create two gesture recognizers:

override func didMove(to view: SKView) {
    let panGestureRecognizer = UIPanGestureRecognizer()
    panGestureRecognizer.addTarget(self, action: #selector(panGestureAction(_:)))
    view.addGestureRecognizer(panGestureRecognizer)
        
    let pinchGestureRecognizer = UIPinchGestureRecognizer()
    pinchGestureRecognizer.addTarget(self, action: #selector(pinchGestureAction(_:)))
    view.addGestureRecognizer(pinchGestureRecognizer)
}

The panGestureRecognizer will handle pan gestures: fingers moving around on the screen.

The pinchGestureRecognizer will handle pinches: multiple fingers zooming in and out.

The didMove(to:) function is called when the scene has moved to the view. This is a good place to instantiate the gesutre recognizers, since they’ll need to be added to the view.

For each of the gesutre recognizers, we add a target to point to a specific function to handle the gesture. Create two new functions:

@objc private func panGestureAction(_ sender: UIPanGestureRecognizer) {
}

@objc private func pinchGestureAction(_ sender: UIPinchGestureRecognizer) {
}

The @objc keyword is needed to expose the instance method to Objective-C.

Add the following properties above the methods to keep track of the camera’s previous scale and position:

private var previousCameraScale = CGFloat()
private var previousCameraPosition = CGPoint()

Inside panGestureAction(), add the following code:

guard let camera = self.camera else { return }
        
if sender.state == .began {
    previousCameraPosition = camera.position
}
        
let translationScale = camera.xScale
let panTranslation = sender.translation(in: self.view)
let newCameraPosition = CGPoint(
    x: previousCameraPosition.x + panTranslation.x * -translationScale,
    y: previousCameraPosition.y + panTranslation.y * translationScale
)
        
camera.position = newCameraPosition

First, we ensure that the scene’s camera is not nil using a guard statement.

If the gesture has begun, set the previousCameraPosition to the current camera position.

The translationScale is used to speed up or slow down the pan gesture according to the scale/zoom level of the camera. If zoomed out, the camera should move faster than when zoomed in.

With the sender’s translation(in:) method, we can get the current translation of the pan gesture.

For every axis, we multiply the translation with the translation scale and add it to the previous position.

Lastly, we set the new camera position.

Inside pinchGestureAction(), add the following code:

guard let camera = self.camera else { return }
        
if sender.state == .began {
    previousCameraScale = camera.xScale
}
        
camera.setScale(previousCameraScale * 1 / sender.scale)

First, check the camera again.

If the pinch gesture has begun, save the previous camera scale.

Lastly, set the camera scale. Because we’re scaling the x- and y-axis here uniformly, we could use xScale before when we wanted to know the scale of the camera.

You should now be able to pan around and zoom in and out of the floor plan.

Drawing openings

You might have noticed that when only drawing walls you get a full perimeter of your room, even though doors, openings and windows are not included yet. This is because a wall spans the full length of the surface and is not ‘interrupted’ by any openings or doors. In other words, a wall is not split into two walls when there is a door in between.

This doesn’t make sense for a floor plan, but it does make sense when viewing the 3D model of the room. Windows are embedded in the wall and the wall continues above and under the window.

Because doors, openings and wall occupy the same coordinates on our 2D floor plan as walls, we need to ‘hide’ walls where openings, doors and windows are.

Create a new function in FloorPlanSurface:

private func drawOpening() {
    let openingPath = createPath(from: pointA, to: pointB)
        
    // Hide the wall underneath the opening
    let hideWallShape = createShapeNode(from: openingPath)
    hideWallShape.strokeColor = floorPlanBackgroundColor
    hideWallShape.lineWidth = hideSurfaceWith
    hideWallShape.zPosition = hideSurfaceZPosition
        
    addChild(hideWallShape)
}

We get the path for the opening again by utilizing our computed values for pointA and pointB and the createPath(from:to:) function.

Next, we create a shape from the path, just like before. However, this time we’re not trying to draw a visible line, but rather hide the wall underneath. Thus, we change the color of the stroke to be the same as our background color. The line width should be slightly wider than that of the walls in order to cover them fully.

Lastly, the zPosition of a node defines whether it is placed on top of other nodes. A higher z-position means the node is closer to the viewer or drawn ‘on top’ of nodes with a lower z-position. The default value is 0.0. If multiple sibling nodes share the same z-position, they are rendered in the order that they appear in their parent’s children array. We want to make sure the shape to hide walls is always on top of the walls, so we set it’s zPosition to a higher value.

Add the hideSurfaceWidth and hideSurfaceZPosition constants to DrawParameters:

let hideSurfaceWith: CGFloat = 24.0

let hideSurfaceZPosition: CGFloat = 1

In FloorPlanSurface, change the if-statement in the initializer:

if capturedSurface.category == .wall {
    drawWall()
}

to a switch-statement:

switch capturedSurface.category {
case .opening:
    drawOpening()
case .wall:
    drawWall()
default:
    drawWall()
}

This will allow us to add more cases later for doors and windows. Because we’re not covering all possible cases yet, we’ll provide a default and draw a wall for windows and doors.

If you run the app now, you should see walls that are interrupted by openings. Chances are you don’t have a room with openings. To test if openings are drawn correctly, you can temporarily change case .opening to case .window to draw an opening for every window in your room.

Drawing windows

For the windows, we’re going to draw a thin line. To do this, we first need to hide the wall underneath, just like we did with an opening. Then we draw a thin line on top.

Create a new method to draw a window:

private func drawWindow() {
    let windowPath = createPath(from: pointA, to: pointB)
        
    // Hide the wall underneath the window
    let hideWallShape = createShapeNode(from: windowPath)
    hideWallShape.strokeColor = floorPlanBackgroundColor
    hideWallShape.lineWidth = hideSurfaceWith
    hideWallShape.zPosition = hideSurfaceZPosition
        
    // The window itself
    let windowShape = createShapeNode(from: windowPath)
    windowShape.lineWidth = windowWidth
    windowShape.zPosition = windowZPosition
        
    addChild(hideWallShape)
    addChild(windowShape)
}

Because all shapes occur on the same path, we need to create just one path. From that path we create two shapes: one to hide the wall and one to draw the window itself. The z-positions are set so the hideWallShape is on top of the wall and the windowShape is on top of the hideWallShape.

The windowWidth and windowZPosition contants are new. Add them to DrawParameters.swift:

let windowWidth: CGFloat = 8.0

let windowZPosition: CGFloat = 10

Add the call to drawWindow() to the switch-statement in the initializer:

switch capturedSurface.category {
case .opening:
    drawOpening()
case .wall:
    drawWall()
case .window:
    drawWindow()
default:
    drawWall()
}

Drawing doors

Now for the last of the surface types: doors. To draw a door, we hide the wall underneath again. Instead of drawing the door on the same path, we want to rotate the door as if it’s open. In addition, we’ll create an arc that represents the door’s swing.

Figure 2: drawing a door

To draw a door, we need a new pointC in addition to our pointA and pointB.

private var pointC: CGPoint {
    return pointB.rotateAround(point: pointA, by: 0.25 * .pi)
}

pointC is calculated by rotating pointB around pointA by a certain angle. Create a new file CGPoint+RotateAround and implement rotateAround(point:by:) as an extension to CGPoint:

import CoreGraphics

extension CGPoint {
    
    func rotateAround(point: CGPoint, by angle: CGFloat) -> CGPoint {
        // Translate to origin
        let x1 = self.x - point.x
        let y1 = self.y - point.y
        
        // Apply rotation
        let x2 = x1 * cos(angle) - y1 * sin(angle)
        let y2 = x1 * sin(angle) + y1 * cos(angle)
        
        // Translate back
        let newX = x2 + point.x
        let newY = y2 + point.y
        
        return CGPoint(x: newX, y: newY)
    }
    
}

This method can be called on a CGPoint and will calculate the new position of the point rotated around another point by a certain angle. The angle is in radians. This means that 2 * pi is a full 360 degree rotation. 1 * .pi therefore is half a rotation and 0.25 * .pi is 1/8 of a rotation. This seems like a nice amount for our door.

Back in FloorPlanSurface, create a new method to draw a door:

private func drawDoor() {
    let hideWallPath = createPath(from: pointA, to: pointB)
    let doorPath = createPath(from: pointA, to: pointC)

    // Hide the wall underneath the door
    let hideWallShape = createShapeNode(from: hideWallPath)
    hideWallShape.strokeColor = floorPlanBackgroundColor
    hideWallShape.lineWidth = hideSurfaceWith
    hideWallShape.zPosition = hideSurfaceZPosition
        
    // The door itself
    let doorShape = createShapeNode(from: doorPath)
    doorShape.lineCap = .square
    doorShape.zPosition = doorZPosition
}

First, we create two paths: one for hiding the wall and one for drawing the door itself. For the doorPath, we take pointC instead of pointB so we get an opened door. Then we create shapes for both paths again.

Now for the arc, add the following to drawDoor():

// The door's arc
let doorArcPath = CGMutablePath()
doorArcPath.addArc(
    center: pointA,
    radius: halfLength * 2,
    startAngle: 0.25 * .pi,
    endAngle: 0,
    clockwise: true
)
        
// Create a dashed path
let dashPattern: [CGFloat] = [24.0, 8.0]
let dashedArcPath = doorArcPath.copy(dashingWithPhase: 1, lengths: dashPattern)

let doorArcShape = createShapeNode(from: dashedArcPath)
doorArcShape.lineWidth = doorArcWidth
doorArcShape.zPosition = doorArcZPosition

Instead of a straight path with a line from one point to another, this path is created by creating an arc. The arc needs a center point (pointA), a radius (the full lenght of the door, or the length from A to B) and a start and end angle. We can also specify the direction of the arc: ether clockwise or anti-clockwise.

To improve the look of the arc, we’ll dash the line. This is done by providing a dash pattern and copying the path using the dashPattern to create a new path.

The doorArcShape is created like all other shapes.

Add the new constants to DrawParameters:

let doorArcWidth: CGFloat = 8.0

let doorZPosition: CGFloat = 20
let doorArcZPosition: CGFloat = 21

Back in FloorPlanSurface, add the new shapes to the surface node at the end of drawDoor():

addChild(hideWallShape)
addChild(doorShape)
addChild(doorArcShape)

Update the switch-statement in the initializer:

switch capturedSurface.category {
case .door:
    drawDoor()    
case .opening:
    drawOpening()
case .wall:
    drawWall()
case .window:
    drawWindow()
@unknown default:
    drawWall()
}

The switch-statement now covers all possible surface categories so we could remove the default. Xcode is warning us though that in future updates of the RoomPlan API, more cases might be added. That’s why it’s suggested we add a default for unkown cases.

Drawing objects

The floor plan is now drawn with all possible surfaces, but it’s still looking a bit empty. We’ll fill up the room with the scanned objects.

Create a new file FloorPlanObject. In here, create a new class FloorPlanObject and an initializer:

import SpriteKit
import RoomPlan

class FloorPlanObject: SKNode {

    private let capturedObject: CapturedRoom.Object
    
    init(capturedObject: CapturedRoom.Object) {
        self.capturedObject = capturedObject
        
        super.init()
        
        // Set the object's position using the transform matrix
        let objectPositionX = -CGFloat(capturedObject.transform.position.x) * scalingFactor
        let objectPositionY = CGFloat(capturedObject.transform.position.z) * scalingFactor
        self.position = CGPoint(x: objectPositionX, y: objectPositionY)
        
        // Set the object's zRotation using the transform matrix
        self.zRotation = -CGFloat(capturedObject.transform.eulerAngles.z - capturedObject.transform.eulerAngles.y)
    }
    
    required init?(coder aDecoder: NSCoder) {
        fatalError("init(coder:) has not been implemented")
    }

}

This code is similar to that of FloorPlanSurface. The initializer now accepts a CapturedRoom.Object instead of a CapturedRoom.Surface but still sets the object’s position and rotation in the same way.

Add a new method to draw an object:

private func drawObject() {
    // Calculate the object's dimensions
    let objectWidth = CGFloat(capturedObject.dimensions.x) * scalingFactor
    let objectHeight = CGFloat(capturedObject.dimensions.z) * scalingFactor
        
    // Create the object's rectangle
    let objectRect = CGRect(
        x: -objectWidth / 2,
        y: -objectHeight / 2,
        width: objectWidth,
        height: objectHeight
    )
        
    // A shape to fill the object
    let objectShape = SKShapeNode(rect: objectRect)
    objectShape.strokeColor = .clear
    objectShape.fillColor = floorPlanSurfaceColor
    objectShape.alpha = 0.3
    objectShape.zPosition = objectZPosition
       
    // And another shape for the outline 
    let objectOutlineShape = SKShapeNode(rect: objectRect)
    objectOutlineShape.strokeColor = floorPlanSurfaceColor
    objectOutlineShape.lineWidth = objectOutlineWidth
    objectOutlineShape.lineJoin = .miter
    objectOutlineShape.zPosition = objectOutlineZPosition
        
    // Add both shapes to the node        
    addChild(objectShape)
    addChild(objectOutlineShape)
}

The object’s width and height are calculated using the dimensions property of the CapturedRoom.Object, just like with surfaces. The difference here is that we’re interested in the z-axis as well, whereas for surfaces, we were just looking for the x-axis or the length of the surface.

Because we’re not just drawing a single line anymore, we then create a rectangle instead of a path. The origin of the rectangle is located in the lower-left corner and the rectangle extends towards the upper-right corner. When we set the node’s position and rotation using transform however, we expected the rectangle’s position to be in the center. This is why we subtract half of the width and height to get the x- and y-position of the rectangle.

Figure 3: creating the object’s rectangle

I like giving the objects a seperate outline and fill. That’s why I created two shapes. The objectShape has no stroke and a low opacity (alpha). The objectOutlineShape has a clearly defined stroke. The lineJoin is set to .miter so we get nice sharp corners.

Add the new constants to DrawParameters:

let objectOutlineWidth: CGFloat = 8.0

let objectZPosition: CGFloat = 30
let objectOutlineZPosition: CGFloat = 31

In FloorPlanObject, call the function at the end of the initializer:

drawObject()

In FloorPlanScene, add a function to draw all objects:

private func drawObjects() {
    for object in objects {
        let objectNode = FloorPlanObject(capturedObject: object)
        addChild(objectNode)
    }
}

And call it at the end of the initializer:

drawObjects()

If you run the app and scan a room, you should be able to view the result as a 2D floor plan.

Conclusion

In Part I, we created a SwiftUI setup that lets users scan their room using the RoomPlan API and it’s scan guidance features.

In Part II, we converted the scan results into a 2D floor plan using SpriteKit. The floor plan contains all scanned surfaces (doors, openings, walls and windows) and objects.

The complete code for this tutorial can be found on my github page: RoomPlan 2D.

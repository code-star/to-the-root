Part 2 - Tutorial: 🚀 Building an AI Assistant using Langgraph tools

by
Peter Eijgermans
,
DiegoLigtenberg

Welcome to the second part of our MCP series! In part 1, we learned the core concepts of the Model Context Protocol (MCP). Now, we're putting that theory into practice.

Share

Click here for the previous article: Part 1 - 🚀 Understanding MCP: What, Why, and How

 

Imagine you're building a helpful AI assistant for your team that can handle various tasks efficiently. You want to create a smart helper that can perform calculations, provide weather information, and answer generic questions while your team focuses on their work. So you decide to build an AI Assistant: a versatile tool that can handle mathematical operations, generate weather reports, and provide general assistance using advanced AI capabilities. That's our mission for this tutorial. We'll build this AI assistant in Python, using FastAPI as our communication foundation and LangGraph as our intelligent processing engine.

 

For this tutorial, we'll focus on implementing the core functionality in main.py. The rest of the setup and supporting code can be cloned directly from Git, so you don't have to start from scratch.

Prerequisites

Python 3.13+ installed

UV Package manager installed

Git installed (to clone the starter code)

Basic Python knowledge

Section 2: Core Command Infrastructure

3. The Lifespan Manager (Your Quartermaster)

 

This code initializes your FastAPI application and configures the LangGraph app during startup. This is similar to how your quartermaster prepares all the equipment before the mission begins.

@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.langgraph_app = await setup_langgraph_app()
    yield

app_instance = FastAPI(lifespan=lifespan)

 
static_dir = os.path.join(os.path.dirname(__file__), "..", "static")
app_instance.mount(
    "/static",
    StaticFiles(directory=static_dir),
    name="static"
)



What's Happening Here: 

  1. @asynccontextmanager - Magic that handles startup/shutdown
  2. lifespan function: Prepares our tools for operation. It loads our LangGraph AI app and saves it to app.state, like packing all your tools into a backpack for easy access.
  3. FastAPI() - Creates our actual server
  4. static_dir: Serves static files for our custom chatbot interface.

10. LangGraph Setup (AI Assistant)


This is the most crucial part: building the LangGraph application that will serve as our AI assistant. This allows the system to think, use tools, and remember conversations while remaining in its role.
 

Python

async def setup_langgraph_app():
    """Setup the LangGraph app, model, tools, and graph. Returns the compiled app."""
    load_dotenv()
    llm = await get_llm()
    tools = await get_tools()

    # Connects tools to the AI
    llm_with_tools = llm.bind_tools(tools=tools)

    # Define the prompt template for the generic AI assistant
      prompt = ChatPromptTemplate.from_messages([
        ("system", (
            "You are a helpful AI assistant. You can answer questions or perform calculations, and wheather information, using the tools provided. "
            "Be clear, concise, and helpful in your responses. When using tools, explain what you're doing to assist the user."
        )),
        ("user", "{input}")
    ])

     # Links personality with AI brain
    chain = prompt | llm_with_tools 

    async def model(state: AgentState):
         # Takes user message and gets AI response
        user_message = state["messages"]
        response = await chain.ainvoke({"input": user_message})
        return {"messages": [response]}

    def tools_router(state: AgentState):
    # Checks if AI wants to use tools
        last_message = state["messages"][-1]
        if hasattr(last_message, "tool_calls") and len(last_message.tool_calls) > 0:
            return "tool_node"
        else:
            return END

    tool_node = ToolNode(tools=tools)

  # Creates empty workflow
    graph = StateGraph(AgentState)
  # Adds thinking step
   graph.add_node("model", model)
  # Adds tool-using step
    graph.add_node("tool_node", tool_node)
  # Starts with thinking
    graph.set_entry_point("model")
  # Decides to use tools or not
    graph.add_conditional_edges("model", tools_router)
  # After tools, go back to thinking
    graph.add_edge("tool_node", "model")

  # Creates database
    conn = await aiosqlite.connect("checkpoint_06.sqlite")
    #  Makes workflow remember conversations
    memory = AsyncSqliteSaver(conn=conn)
    # Puts all parts together
    app = graph.compile(checkpointer=memory)
  # Returns the ready-to-use AI commander/langgraph app
    return app

 

Here's 9-step flow breakdown of the setup_langgraph_app() process:

  1. Input Received: User message enters the system via state["messages"] 
  2. Model Processing: LLM analyzes the message with the commander persona prompt 
  3. Decision Point: AI determines if it can answer directly or needs tools 
  4. Direct Response Path: If no tools needed → returns final answer immediately 
  5. Tool Activation: If tools required → identifies which tools with parameters 
  6. Tool Execution: Runs all necessary tools in parallel (e.g., logistics/intel checks) 
  7. Collects and formats all tool outputs 
  8. Final Synthesis: Returns to LLM to craft human-readable response using tool data
  9. Stores full interaction in SQLite database

 

Section 7: Communication Channel

11. The /chat Endpoint (Radio)


The next POST-endpoint handles real-time AI chat interactions, processing user messages through the LangGraph app (see section 12) and streaming back: 

  • Immediate "thinking" responses
  • Live tool execution updates 
  • Final formatted answers 

     

Python

# Endpoint for chat interactions

@app_instance.post("/chat")
async def chat_endpoint(request: Request, user_input: str = Form(...), thread_id: str = Form(None)):
    print("Received user_input:", user_input)
    # Set default thread ID if none provided
    if not thread_id:
        thread_id = "demo-user-1"
    # Configure conversation tracking
    config = {"configurable": {"thread_id": thread_id}}
  # Access our pre-configured LangGraph app
    langgraph_app = app_instance.state.langgraph_app
  
    # Real-time event stream generator
    async def event_stream():
        final_message = None
        async for event in langgraph_app.astream_events(
      # Format user input
            {"messages": [HumanMessage(content=user_input)]},
            # Pass conversation config
           config=config
        ):
            print("Event:", event)
              # Handle AI "thinking" events
            if event.get("event") == "on_chat_model_stream":
                chunk = event["data"]["chunk"]
                if hasattr(chunk, "content") and chunk.content:
                    yield chunk.content + " "
              
              # Handle tool initiation events
            elif event.get("event") == "on_tool_start":
                tool_name = event.get("name", "tool")
                tool_args = event.get("data", {}).get("input", {})
                yield f"\n__TOOL_CALL__:Calling tool '{tool_name}' with args {tool_args}\n"
            
       # Handle tool completion events
             elif event.get("event") == "on_tool_end":
                tool_name = event.get("name", "tool")
                tool_output = event.get("data", {}).get("output", "")
                state = event.get("data", {}).get("state", {})

                  # Special formatting for logistics reports
                if tool_name == "logistics_agent" and "logistics_messages" in state and state["logistics_messages"]:
                    latest = state["logistics_messages"][-1]
                    yield f"\n__LOGISTICS__:{latest}\n"
                  
                  # Special formatting for intel reports 
               elif tool_name == "intel_agent" and "intel_messages" in state and state["intel_messages"]:
                    latest = state["intel_messages"][-1]
                    yield f"\n__INTEL__:{latest}\n"
                
                else:
           # Default tool output format
                    yield f"\n__TOOL_CALL_RESULT__:Tool '{tool_name}' returned: {tool_output}\n"
      
         # Handle final response events  
                elif event.get("event") in ("on_chain_stream", "on_chain_end"):
                messages = []
                if "data" in event and "chunk" in event["data"] and "messages" in event["data"]["chunk"]:
                    messages = event["data"]["chunk"]["messages"]
                elif "data" in event and "output" in event["data"] and "messages" in event["data"]["output"]:
                    messages = event["data"]["output"]["messages"]
                if messages:
                        # Capture final response
                    final_message = messages[-1].content
        if final_message:
            yield f"\n__FINAL__:{final_message}"
    # Return the streaming response to client
    return StreamingResponse(event_stream(), media_type="text/plain")


This diagram shows the complete flow of this chat POST-endpoint code:

  1. Input Processing - Receiving user input and setting up thread tracking
  2. Event Stream Setup - Configuring the LangGraph application and creating the async event stream
  3. Event Type Handling - The main decision tree that processes different event types
  4. Tool-Specific Formatting - How different tools get special output formatting
  5. Stream Response Flow - The continuous loop that processes events until completion

Mission Accomplished! 

Congratulations—you’ve just built an MCP-powered AI assistant that can:  

  • Process requests intelligently (using LLMs)  
  • Call tools dynamically (like fetching data or performing calculations)  
  • Stream responses in real-time (no more waiting for full replies)  
  • Remember conversations (thanks to SQLite persistence)  

 

Core Lessons Recap

  • Think of tools as specialists: give them clear inputs and outputs with type hints, explain their purpose in docstrings, and make them async so they don’t block.

     
  • LangGraph is the AI’s brain: it maintains state, decides when to think or act, and routes naturally between the LLM and tools.

     

  • FastAPI is the bridge to users: it streams updates in real time and structures responses with markers like __TOOL_CALL__.

     

Final Thoughts  

By now, you’ve built a solid foundation for working with MCP: a modular AI system that goes beyond simple chat. With FastAPI, LangGraph, and your custom tools in place, you now have an AI that can handle calculations, gather intel, and manage tasks in a structured way.

This setup isn’t limited to the example we built here. The same foundation can be applied to customer support bots, personal assistants, or workflow automation systems. It’s flexible, extensible, and ready for real-world use.

Semantic Search and Filter for Dutch House of Representatives Motions

by
Coen.Goedhart

An idea came to me during last year’s Dutch House of Representatives elections. While reading party election manifestos (verkiezingsprogramma’s in Dutch), I noticed a gap between party promises and their actual voting behaviour on motions (moties in Dutch). The official website, tweedekamer.nl, makes it difficult to track down relevant information on these motions.

This blog explains my project creating the website ikzoekeenmotie.nl using a Weaviate vector database to enable semantic search and filtering capabilities to find relevant motions of the House of Representatives.

Difficulties of finding relevant motions on tweedekamer.nl

Trying to search for relevant motions on a certain subject on the official website, tweedekamer.nl, proved to be quite challenging. The website only shows the subject of the motion and not the full text, which must be downloaded separately. Since the motion titles are often not descriptive, I frequently discovered that after downloading the full text, it was not relevant to my search query. Another challenge is the lack of filtering options. It is not possible to filter motions to display only those that have been voted on, or to sort them by acceptance, rejection, or specific party votes.

Challenge accepted!

After some digging, I discovered that these motions are accessible via opendata.tweedekamer.nl. The schema of the API is shown below and contains valuable data that is worth exploring.

Schematic of open data from https://opendata.tweedekamer.nl/

Using this API, I retrieved and downloaded the full text of all motions from 2015 onwards. I then filtered the dataset to include only voted motions, resulting in about 28,000 records. When reviewing the texts of motions, I noticed they often use specific language such as “Gehoord de beraadslaging” and “constaterende dat,” making it difficult to quickly grasp the essence of a motion. Users have to read or skim through the entire text to determine its relevance. To address this issue, I created short summaries so users can effortlessly understand the essence of each motion at a glance.

I generated two-sentence summaries based on the subject and the motion text using a combination of the Gemini API (when it was still free) and OpenAI. Here is an example of a prompt and its generated summary, designed to make the motion easier to understand:

Setting up a vector database

Having a dataset and generated summaries, the next step is to improve the search and filtering capabilities for these motions. For this, I went with Weaviate, an open-source vector database with Dutch roots. This database makes it possible to find motions based on context along traditional keyword search and filtering capabilities.

The ability to search based on context is achieved through the use of embeddings. Embeddings are a way to represent text data as dense vectors of real numbers. These vectors are generated in such a way that semantically similar pieces of text are represented by vectors that are close to each other in the vector space. The process of transforming text into vectors is called vectorisation.

First, I created a collection in my Weaviate database. For most properties, I set skip_vectorization to true, as I didn't want these properties included in the vectors.

import weaviate
import weaviate.classes.config as wc

client = weaviate.connect_to_local()
client.collections.create(
    "Moties",
    vectorizer_config=Configure.Vectorizer.text2vec_openai(
        model="text-embedding-3-small"
    ),
    properties=[
        wvc.config.Property(name="document_id", data_type=wvc.config.DataType.TEXT, skip_vectorization=True),
        wvc.config.Property(name="date", data_type=wvc.config.DataType.DATE, skip_vectorization=True),
        wvc.config.Property(name="vote_result_boolean", data_type=wvc.config.DataType.BOOL, skip_vectorization=True),
        wvc.config.Property(name="votes_for", data_type=wvc.config.DataType.TEXT_ARRAY, skip_vectorization=True),
        wvc.config.Property(name="votes_against", data_type=wvc.config.DataType.TEXT_ARRAY, skip_vectorization=True),
        wvc.config.Property(name="subject", data_type=wvc.config.DataType.TEXT),
        wvc.config.Property(name="motion_text", data_type=wvc.config.DataType.TEXT),
        wvc.config.Property(name="motion_summary", data_type=wvc.config.DataType.TEXT),
    ]
)

To generate the embeddings of the texts, various embedding models can be used. For simplicity, I used an embedding model from OpenAI. I parsed the voting records into a list of parties that voted for and against each motion (this might not be the most elegant way, but it works). Then, I loaded the motions into the database as follows:

import weaviate
from weaviate.util import generate_uuid5

client = weaviate.connect_to_local()
collection = client.collections.get("Motions")

with collection.batch.dynamic() as batch:
    for data_row in data:
        obj_uuid = generate_uuid5(data_row['document_id'])
        batch.add_object(
            properties=data_row,
            uuid=obj_uuid
        )

Querying the vector database

Now, with this collection, we can perform various queries. One approach is to use a keyword search algorithm to find specific motions. Keyword search is a basic technique finds documents containing the exact terms provided in a query. In Weaviate, we can utilize the bm25, a more advanced keyword search algorithm. BM25 also considers factors such as term frequency, inverse document frequency, and document length to rank documents. This allows to retrieve motions that are most likely relevant to the keywords in the user’s query.

collection = client.collections.get("Motions")
response = collection.query.bm25(
    query="Education",
    limit=10
)

We can also perform a vector search using the near_text function. This approach embeds the search query to the same high-dimensional vector space as the motions stored in the collection. By comparing the angles of the vectors, we can find documents that are contextually similar to the query. This method captures the semantic meaning of the text, allowing for more accurate retrieval of relevant motions, even if the exact keywords are not present. This makes it particularly useful for understanding the context and intent behind the motions.

collection = client.collections.get("Motions")
response = collection.query.near_text(
    query="Education",
    limit=10,
)

In addition, we can combine BM25 with vector search using a hybrid approach. This method leverages the strengths of both keyword-based and semantic search by combining their results. The parameter “alpha” determines the balance between BM25 and vector search, with higher values giving more weight to the vector search results. Additionally, we can apply filters to refine our search, such as specifying lists of parties that voted for or against the motions.

collection = client.collections.get("Motions")
response = collection.query.hybrid(
    query="Education",
    filters=
        wvc.query.Filter.by_property("votes_for").contains_all(['D66']) &
        wvc.query.Filter.by_property("votes_against").contains_all(['CDA']),
    alpha=0.5,
    limit=10,
)

Exploring the motions and optimizing search settings

It was fun to explore the motions using these queries. Besides the queries above, another way of exploring the motions is to find similar motions based on a existing motion in the collection. Instead of using a search query, the vector of an existing motion is used as input to find similar records. This can be performed by the following query:

collection = client.collections.get("Motions")
response = collection.query.near_object(
    near_object=generate_uuid5('2022D52728'),
    limit=10,
)

I noticed that finding similar motions using the near_object function worked really well. Finding similar motions based on the example motion above regarding AI, the results include a highly similar motion that was rejected a year before. Additionally, the search returns motions on topics such as the impact of AI in education, reducing AI-related risks in society, and using AI within municipalities.

I particularly enjoyed searching for motions similar to recent ones and discovered that these motions often had a lot in common, providing insights into recurring themes.

However, when using the near text function in combination with my own queries, the results were often not relevant. This could be due to several common disadvantages of relying solely on vector search. One issue is that the OpenAI small embedding model might not be the best model to use for Dutch language. Additionally, the query might be too short to translate effectively into a high-dimensional vector, reducing the accuracy of the search. Results retrieved using only keyword search were similar to those on the original website, tweedekamer.nl, often missing relevant documents because the motions did not include the specific keywords.

Therefore, hybrid search worked really well by just giving the vector search a small influence combined with keyword search. A low alpha value worked best, as it balanced the strengths of both keyword and vector search, improving the relevance of the results and ensuring a more comprehensive retrieval of motions.

Potential Improvements

There are several improvements that could be made to enhance the search functionality. Currently, both BM25 and near text search return a fixed number of documents, with a limit set at 10. However, this approach has limitations. There might be fewer or more relevant documents but it will always return 10 results. This could be optimised by dynamically adjusting the number of returned documents based on their relevance, and by implementing a relevance score threshold to ensure only documents that meet a certain level of relevance are included in the results.

Another improvement could involve using an embedding model specifically trained on Dutch. Weaviate has a feature where you can insert your own vectors, allowing for better handling of Dutch-specific language nuances and potentially improving search accuracy.

Additionally, incorporating various Retrieval-Augmented Generation (RAG) features could significantly enhance search results. For example, query expansion can be used to improve the user query by adding related terms or synonyms, ensuring a broader and more accurate search. In addition, Reranking involves reordering the initial search results to better assess their relevance based on additional criteria or a more sophisticated ranking algorithm [1]. These techniques could help in better understanding and ranking the search results.

Conclusion, try it out yourself!

Ultimately, using a vector database to search motions proved effective. Combining traditional keyword search with semantic search showed strong potential for contextual search and relevance, although there is still room for improvement . Particularly, using an embedding model better suited for Dutch and implementing advanced RAG features could improve search results significantly.

If you would like to explore motions yourself, visit the website I created: ikzoekeenmotie.nl.
